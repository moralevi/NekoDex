# NekoDex: specification and roadmap

Dalamud plugin for FFXIV that shows what the logged-in character owns and is missing, how to unlock the rest, and what resets when. Friends first; public repository planned. This file is the current state plus the plan; the phase-by-phase history with every gate lives in [docs/spec-history.md](docs/spec-history.md).

Method: phased, each phase has a scope and a gate. A phase starts only when the previous gate passes. In-game gates are checked by the user; unit-testable logic lives in `NekoDex.Core`.

## 1. What it is today (after Phases 0-20, 2026-10-16)

- **Collections:** Mounts, Minions, Orchestrion, Emotes, Bardings, Fashion Accessories, Facewear, Triple Triad. Each tab: owned/missing with progress, search, ownership and obtainable filters, "new in patch X", sortable columns, pins, and a detail pane with unlock text, patch and web link.
- **Unlock data:** bundled `unlocks.json` generated by `tools/DataGen` from FFXIV Collect, with Garland Tools filling gaps by item id; every entry carries its item id and source. Links go to FFXIV Collect pages or Garland item pages. A weekly workflow proposes refreshes as pull requests.
- **Dashboard:** reset countdowns (daily, weekly, Grand Company, Jumbo Cactpot, Fashion Report) in local time, per-collection progress, new-this-patch rows, and a checklist with manual items plus game-read auto items (roulettes, tribal allowances, Wondrous Tails).
- **Mini window:** daily and weekly countdowns, open to-dos, pinned entries.
- **Settings:** open on login, mini window, auto item choices, Neko theme toggle, language (follow Dalamud or a loc file), link site, export and import of pins, checklist and auto choices.
- **Localisation:** every string through `Strings.Get`; `loc/en.json` generated by `tools/LocExport`; `loc/sv.json` complete; de, fr, ja templates.
- **Removed by decision (2026-10-16):** Armoire tab, outfit planner, gear advisor. Not to be re-added unless asked.

## 2. Hard rules

- No automation of gameplay, no input injection, no botting. Information and UI only. Game memory is read, never written.
- Only the logged-in character is tracked. Per-character caches are allowed; cross-character views are not planned.
- The plugin makes no network calls except where a phase below says so explicitly (Phase 26 adds one manual, user-triggered check).
- Every "game not ready" state (login screen, loading, character select) renders a message instead of touching character data.
- Logic in `Core` (no Dalamud dependency), game reads in `Data`, drawing in `UI`. Adding a collection is a module class plus a registration line, a generator row and a link segment.
- Verify Dalamud API level and ClientStructs usage at the start of each phase. After a game patch follow `docs/patch-day.md`.

## 3. Decisions in force

| Topic | Decision |
|---|---|
| Name and look | `NekoDex`; plum/salmon theme, cat-face icon |
| Audience | Friends first; the user plans to make the repo public |
| Languages | English and Swedish; Swedish selectable in settings because Dalamud lacks it |
| Unlock sources | FFXIV Collect first, Garland Tools second; both need a redistribution OK before public release (see DATA_SOURCES.md and docs/outreach.md) |
| Resets | daily 15:00 UTC, weekly Tue 08:00 UTC, Grand Company 20:00 UTC, Jumbo Cactpot Sat 19:00 UTC, Fashion Report Fri 08:00 UTC |
| Auto items | every duty roulette offered; tribal done at 0 of 12 left; Wondrous Tails done at 9 stickers; defaults expert, leveling, tribal, plus alliance raids and Wondrous Tails from Phase 22 |
| Obtainable | Premium, Event and legacy sources count as not obtainable; from Phase 21 so do entries with no item and no source |
| Data refresh | weekly GitHub workflow opens a pull request; CI runs DataGen without game files |
| Changelog | single 1.0.0 entry for the first release |
| Tests | xUnit over Core; plugin side verified in game |

## 4. Open decisions

- Boss-kill counter scope (Phase 24): count every duty completion, or only duties tied to a pinned or missing mount. Needed before Phase 24.
- Hairstyle gate (Phase 25): FFXIV Collect's count is the reference since the game has no hairstyle guide; confirm that is acceptable at the gate.
- "Check for newer data" (Phase 26): where the version marker is read from (repo.json on the public repo is the plan once public).

## 5. Roadmap, Part 4 (planned 2026-10-16)

### Phase 21: Housekeeping

Scope
- This document replaces the old spec; the old one moves to `docs/spec-history.md`. (Done with this commit.)
- Changelog folded into one 1.0.0 entry. (Done with this commit.)
- `docs/outreach.md` with the FFXIV Collect and Garland Tools permission messages, ready to send. (Done with this commit.)
- Entries with no item id and no source are marked not obtainable (they are legacy or promotional) instead of Unknown, with the detail pane saying why.
- DataGen gains `--sheets-only`: runs every module's sheet rule against the local game files with no network, as the patch-day smoke test. Recommendation from the developer: this is the cheap version of a plugin smoke test; a harness that boots the real modules would need a fake `IDataManager` and is not worth it yet.

Gate
- [x] `--sheets-only` runs in under a minute and prints per-module counts.
- [x] Legacy entries show as not obtainable with a reason.

### Phase 22: Dashboard and mini window polish

Scope
- Checklist first on the Dashboard, then resets, collections, new this patch.
- Reset toast: when a daily or weekly reset passes while logged in, show a Dalamud toast naming the reset; option to turn it off.
- Mini window: lock (no move), clickthrough, and an opacity slider in settings; `/nekodex mini lock` toggles the lock.
- Auto item defaults extended with alliance raid roulette and Wondrous Tails for new installs; existing configs unchanged.

Gate
- [x] Toast appears once per reset crossing and not on login.
- [x] Locked clickthrough mini window ignores the mouse and can still be unlocked from settings.

### Phase 23: Triple Triad depth

Scope
- Verify: TripleTriadCardResident acquisition, TripleTriad NPC sheet, ENpcBase to Level rows for coordinates, `IGameGui.OpenMapWithMapLink` for a flag.
  - Verified 2026-10-16: 146 TripleTriad rows, 142 reachable from an ENpcBase data reference, 134 with a Level row (type 8); 333 cards drop from NPCs. `OpenMapWithMapLink(territory, map, Vector3)` takes the Level world position directly. NPC unlock quests come from `TripleTriad.PreviousQuest` with `PreviousQuestJoin` (2 = any, otherwise all).
- Detail pane: NPC name, zone and coordinates for cards won from NPCs; a button that opens the map with a flag at the NPC.
- Filter: "winnable from NPCs you have unlocked", using the NPC's unlock quest completion.
- Sort options: by stars, by type, by number (the in-game deck view order).

Gate
- [ ] Map flag lands on the NPC for 5 spot-checked cards.
- [ ] The winnable filter excludes an NPC whose unlock quest is incomplete and includes one that is complete.

### Phase 24: Mount farming

Scope
- "Farmable now" view: missing mounts whose source is a duty, grouped by duty, with duty level (dungeon, trial, extreme, savage, ultimate) from ContentFinderCondition; a filter to hide Savage and Ultimate.
- Pinned entries in the mini window show their duty name.
- Boss-kill counter: subscribe to Dalamud's duty completion event, map the territory to the duty, and count completions per character per duty; shown next to the duty in the farm view and the mini window, with a reset button. Decide the counting scope (open decision). Dataset entries keep the related instance id for duty sources so the mapping is data-driven.

Gate
- [ ] Completing a trial increments its counter by exactly one and survives a reload.
- [ ] Farm view groups match the duty names in the Duty Finder.

### Phase 25: Glamour-relevant collections

Scope
- Hairstyles: CharaMakeCustomize rows that are purchasable, unlock via unlock link, labelled by race restriction where it applies; gated against FFXIV Collect's count (open decision).
- Framer's kits and portrait items: owned/missing from `PlayerState.IsFramersKitUnlocked`, verifying the kit id to sheet mapping; no unlock data source exists, so links only.
- DataGen rows where an endpoint exists (hairstyles yes, framer's kits no).

Gate
- [ ] Hairstyle count matches FFXIV Collect's and ownership matches the aesthetician list for 10 styles.
- [ ] Framer's kit ownership matches the portrait UI for 10 kits.

### Phase 26: Data trust

Scope
- "Report wrong source" button on the detail pane: copies a prefilled correction text (entry, current source, dataset version) to the clipboard for the user to paste on FFXIV Collect's Discord.
- Manual "check for newer data" in settings: one HTTPS request to the public repo's `repo.json`, compares the embedded dataset date with the released one, and tells the user whether an update exists. Never automatic; the plugin otherwise stays offline.

Gate
- [ ] Clipboard text contains entry name, module, source lines and dataset version.
- [ ] The check reports "up to date" and "newer available" correctly against a test repo.json.

### Release rhythm
- Tag `v1.0.0.0` when the user decides to go public, after the outreach answers are recorded.
- Then one tag per completed Part 4 phase pair.

```
tools/LocExport/         string export and translation check
tests/NekoDex.Core.Tests xUnit
loc/                     translations
docs/                    patch-day checklist, spec history, outreach drafts
```
